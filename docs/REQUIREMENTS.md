# 已确认需求：日记驱动复盘 v0.3

## 2026-10-14：模型理解语义，代码保障写入（0.3.5）

用户认可只读评估并要求继续落实优化。本节覆盖此前日期正则、关键词匹配、逐字日期证据及日期覆盖检查的强制语义判断。

- 日期用途、跨月相对日期、时刻、反馈指代、暂缓/取消、独立安排拆分交给模型理解。用户原有“无日期尽快完成、不因任务量延期、不编造时段”偏好通过提示词保留。代码根据模型的 timing/timeSpecified 分类校验一致性，不再读取自然语言猜测或覆盖日期与时刻。
- 代码保留合法日期/字段、完整 ID、拆分来源、勾选状态、层级、模板、固定写入路径、预览接受、并发检查和回滚。证据引用变为可选；若提供则校验是否确实出自对应原文，不判断是否符合某种日期写法。
- 支持 answer/plan/patch。用户点击“只解释，不改计划”时强制只接受 answer，原草稿不变；默认发送允许模型区分讨论、澄清和调整。局部变更先合并成完整计划，再做所有检查；不得通过 patch 删除来源 ID。
- 对话按用户/助手/校验器顺序传入下一轮，来源旧日记原文也提供为上下文，其他章节仍不可自行转成任务。正常解释与日记总结分离。结构失败包含字段位置，保留旧预览并拒绝错误计划，不静默修正、不自动循环请求。
- 同日本设备重启恢复已归档且未接受的讨论，必须重新读取才能生成新草稿；已接受或跨日讨论不自动恢复为待执行意见。开始新对话清空活动上下文但保留归档。记录包含私人正文，不上传仓库，不包含 API key。
- 明确分类为提醒的新条目不作为占用时段的活动冲突；其他可识别时段冲突继续阻止接受。分类本身仍依赖模型理解，不能把结构校验宣称为语义正确保证。

## 2026-10-14：未来安排、自然语言反馈和持久诊断（0.3.4）

用户要求修复未来任务被强制放入目标日、自然语言调整无法生效，以及无法查看/复制会话的问题，并明确同意保存个人规划内容用于排错。以下覆盖此前“不保存响应正文”的约定；秘密仍不得保存。

- 支持短月日、当月日号、日期范围/并列日号和中文时刻；省略年月以原文日期为基准，反馈以本次今天为基准。不猜测跨年、跨月的省略日期。
- 模型用输入 ID 加逐字证据绑定自然语言改期，允许简称、代词、分组及新增提醒，不要求反馈包含完整原标题。引用必须来自原任务/祖先或用户反馈；最新明确修改优先，任务数量不授权延期。
- 明确包含多个安排的任务可以有依据地拆分成独立条目，必须关联来源 ID、保留层级；多个未来日期未覆盖时禁止接受。识别不出的未来意图提示待确认，不静默放到今天。
- 下一次请求包含模型原提议、插件最终草稿、本地改写原因或错误。界面区分模型说明与最终预览；不自动循环模型请求，也不自动接受草稿。
- 默认将每次请求、反馈、模型正文、最终处理和错误保存到插件目录的设备隔离 conversations 子目录，可从面板查看与复制。截断/结构失败正文也保存；不保存 Authorization、API key、上游 HTTP 错误正文或推理正文。关闭面板/重启后仍可读历史，但历史不是可直接接受的活动草稿。
- 日志没有自动清理；可能随用户对隐藏配置目录的同步/备份规则传播，应按私人笔记保护，不提交 Git 或附加到 Release。部署前保全仍打开的旧会话；0.3.3 只能恢复内存反馈及最后处理结果，无法补回已丢失的历次模型正文。

## 2026-10-12：截断诊断与预览恢复（0.3.3）

用户要求进一步定位并尝试解决模型截断及预览消失问题。显示全部需处理条目数量；截断时只记录安全的数量统计，不泄露响应正文或秘密。提高新安装默认预算，已有设置保留；扩大预算和重试由显式按钮触发，不自动消耗请求额度。失败时保留旧预览供参考，但必须禁止接受，完整新草稿成功后才恢复写入。只用合成回归验证逻辑，不将其视为真实网关已成功生成的证据。

## 2026-10-12：最近一份 TODO 为准（0.3.2）

用户明确在最近一次有 TODO 的旧日记中手动整理、追加，然后生成今日／明日清单。默认读取当前日最新清单；当前日无清单时向前最多 30 天查找最近一份，不以已确认日期排除它，也不混合更早版本。完成勾选、删除、层级与新增内容以当前原文为准。全完成或已登记清单清空后不得恢复更早旧任务。保留日期范围合并为显式高级模式。

未另定日期的任务安排到所选日；到期和过期的跨日任务也默认接续，不能无期限 keep。预览显示实际来源日期。确认前校验查找期间跳过的较新日记是否变化，避免选用了过时清单；这些只读探测日记不进入写入／撤销清单。已知清单边界随 version 2 状态保存，兼容旧数据读取，但所有设备需升级 0.3.2 后再读取新字段。

## 2026-10-09：保留层级、无日期尽快安排（0.3.1）

本节优先于旧规则：任务保留原有父子层级与同级顺序，不能因 Agent 重排而打平。跨日期的子步骤携带原父任务上下文；已完成父项不重新创建为未完成任务。不同父级允许同名步骤。

无明确安排日期表示尽快完成，必须安排到面板所选今天或明天，不因任务量、优先级或估时自动延期或 keep。截止日期不等于开始日期。其他日期必须来自任务原文、父任务、已确认跨日记录或明确点名任务的用户反馈；模型理由不是依据。本地纠正无依据的延期与时间块，仍保留待确认问题和冲突阻止写入。

用户本轮明确授权安装新版发布文件到正式 Vault；测试仅用合成数据，不接受旧草稿、不修改真实日记或配置。

## 2026-10-09：补做日程与清理日记 ID

用户确认：第二阶段暂不开展；第一阶段需适应漏做一天或多天的情况，支持在白天或晚上生成今天或明天的安排。补读遗漏日记、汇总未完成任务供用户确认。保留日记链接，去掉链接后的 ID，减少日记正文中的注释标记。

以下新约定优先于下面 v0.2 中“不回查旧日记”“仅安排明天”“逐任务注释”的旧规定，其余确认、模型校验与写入保护继续保留：

1. 面板明确选择今天/明天。今天模式原位调整当日未完成任务并接续旧任务，明天模式合并新增任务而保留明日已有内容。
2. 只有手动启动才读取数据；补读默认开启，从上次确认后开始，无记录默认近 7 天，可调整起始日，最多近 30 天；明确显示截断范围，不全库扫描。
3. 提供每项任务的原日期，历史相对日期以原日期解释。模型不得把漏做等同于任务完成，所有输入必须有明确去向，预览后才写入。
4. 接续后更新旧任务行的去向，保留原文、链接、勾选及其他章节；缺失旧日记不创建。旧日记的 keep 表示不接续、以后不自动追踪，面板明确告知。
5. 日记不再产生逐任务 `rp` 和 `rp-reviewed` 注释；身份与完成项摘要移至跨日文件 version 2 的 `diaries` 数据中，随 Markdown 同步并参与同一批写入/撤销。保留一对复盘区域边界注释。
6. 兼容读取旧跨日数据和旧注释；确认时仅清理本次相关日记 Tasks 区域的插件注释，不改代码块或无关正文。不执行真实 Vault 的全局清理。
7. 文本完全相同的同日任务要求区分，正文修改后重新识别；身份记录不作为恢复被删除任务的来源。近 30 天之外不保证保留处理摘要，也不自动补读。
8. 并发检查、回滚与撤销扩展到所有补读日记。跨午夜草稿无效，改目标/范围后需重新生成。跨设备分布式原子性依然不保证。

## v0.2 原始需求（与上文冲突处已被替代）

2026-10-05：用户确认样例流程，授权开始实现。继续现有仓库改版；Windows 与 Ubuntu 均为主力，尽量保留 Android 兼容能力，不迁移开发环境。本文件替代 0.1 的独立任务管理需求；旧需求和源码已保存到 dist/research-planner-0.1.1-source.tar.gz。

1. 白天不扫描、识别或索引任务，不调用模型、不改 Vault。用户直接编辑当日日记 `## Tasks` 的 Markdown checkbox；完成靠勾选，不需要的由用户删除。
2. 用户整理完后，手动点击面板“开始复盘”。仅读取当日日记、明日日记（合并与冲突检查）、跨日任务清单和必要的模板/配置。不扫描旧日记，不读取项目或其他 Planning 文件。
3. 无日期任务归属于当日日记日期；相对日期以该日期解析。区分安排日期和截止日期；不强制估时、时间块或优先级打分。
4. 模型输出简短总结和明日任务草稿。用户可以自然语言迭代或直接接受。未来任务也在预览中明确展示；未接受的讨论不写入任何笔记。
5. 确认后同时保存当日复盘、明日 Tasks、跨日清单。现有明日日记保留原有内容，新增任务采用合并；不存在则采用 Daily Notes 配置的模板。日期变量用目标日记日期。
6. 当天任务交接后原文保留并标明去向，不伪装成已完成；目标任务使用稳定内部标识。下一天以该日记 checkbox 为准，删除即不再考虑，不能从历史恢复。
7. 跨日清单只保存已确认但尚未交给某篇日记管理的任务，使用一个 Vault 内 Markdown 文件。写入目标日记后退出清单；未交接的过期条目仍供下次决定，无需读取旧日记。
8. 模板当前实际为内置 Daily Notes/Templates，不运行未知 Templater 脚本。时间轴插件尚未确定：先支持普通 `HH:mm - HH:mm` 和仅开始时间的任务文字，不宣称完成某插件联调。手机日历账户暂不实现。
9. 可选晚间提醒只提醒，不发起复盘或模型调用；应用关闭时不运行。不要求补做漏掉的历史复盘。
10. 每个输入任务都必须得到明确处置，未知/重复/遗漏 ID、模糊待确认问题和可识别时间冲突不得直接写入。保留在当日日记但不交接的任务须明确告知以后不追踪。
11. 确认写入前检查所有输入快照与模板/配置；多文件写入留本机恢复日志，失败尝试恢复；有后续编辑时拒绝覆盖。新建文件撤销后留空而不删除。LiveSync 同时离线写入无法保证分布式原子性，不夸大保护范围。
12. API 密钥使用每台设备的 SecretStorage，调用上限与写入/提醒开关保存在 Vault 隔离的本机存储。插件逻辑不依赖 Node、Electron 或硬编码操作系统路径。
13. 旧版任务目录不自动迁移或删除；用户手动把仍需继续的任务放入当日 Tasks。

所有自动写入、模拟用户输入和 API 验证只用合成 Vault/任务，不修改 Windows 或旧 Linux 正式 Vault。分别报告核心测试、真实 API、真实 Obsidian，以及尚未完成的 Windows/Android/LiveSync 实机验证。

## 2026-10-07：完成项内的后续安排

用户授权修复已勾选条目中明确未来工作的遗漏。手动复盘时检查当日 Tasks 的完成条目及紧随的缩进补充；完成状态与后续工作分开处理。明确后续在预览中展示，确认后使用独立 ID 写入明日或跨日清单，原文与勾选保持。普通完成项不得编造任务，日期／内容不明先问；多项独立后续先请用户拆分或在反馈中明确新增。确认后记录内容摘要标记防止重复提取，正文修改后重查，撤销同步还原标记。白天无扫描、不读取旧日记的边界保持。

部署授权范围：仅更新用户当前安装的 Research Planner 插件发布文件并保留回滚备份；自动化测试仍使用合成 Vault，不修改真实日记或 API 设置。用户已自行启用集中配置，不由部署脚本修改开关。
