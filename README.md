# Research Planner 0.3.5

直接在 Obsidian 日记里记任务，手动选择安排今天或明天，接续最近一份手动整理的 TODO，通过自然语言调整，确认后写入。只有主动生成、发送意见、询问解释或测试连接才调用模型；后台不扫描、不调用模型。安装后不需要 Python、Node.js 或 WSL。

验证范围见 [VALIDATION.md](docs/VALIDATION.md)。合成测试不等于真实模型或多设备验收；正式 Vault 安装须由用户授权，安装不自动接受草稿。

保留 Tasks 中父任务、子步骤与原顺序，预览也显示层级。子步骤独立跨日时保留父级上下文；已完成父级仅作普通文字上下文。无明确安排日期的任务默认尽快处理，放到所选今天或明天，不能因任务太多自动延期；截止日不会让任务等到截止当天才开始。只有明确的原始安排或用户改期意见可以另定日期，没有指定时刻则不自动排时间段。日期语义由模型理解，输出使用标准日期；代码校验日期合法性和动作一致性。

## 安装与升级

**从新机器或交给 Agent 部署，请先读 [完整安装指南](docs/INSTALL.md)。** 推荐在 Obsidian 的 BRAT 中添加公开仓库 `harold-lu-bit/daily-planner`，选择 latest，之后通过 BRAT 检查更新，无需 GitHub token 或本地编译。已有手工安装可由 BRAT 接管，保留 `data.json`。各平台步骤、可复制的 Agent 任务和回退说明均在安装指南中。

维护者按 [发布指南](docs/RELEASING.md) 提交、推送版本 tag，Actions 自动测试、构建并创建带三个独立插件附件的 [GitHub Release](https://github.com/harold-lu-bit/daily-planner/releases)。只推送源码不会让其他设备收到更新。

首次安装提供 [精简日记模板](examples/Daily.md) 与 [非秘密配置示例](examples/plugin-settings.example.json)。沿用原服务商时只需提供 API key、model name 和目标 Vault 的访问权限；更换服务商还需 API base URL。密钥使用 Obsidian SecretStorage，不进入仓库。已有设备只更新插件时无需重新配置模型。

需要开发或从源码安装时：

```sh
git clone https://github.com/harold-lu-bit/daily-planner.git
cd daily-planner
npm ci
npm test
npm run build
```

Windows PowerShell 可将 `npm` 换成 `npm.cmd`。构建后按指南复制三个发布文件，配置模板、密钥和本机写入开关。

1. 保留旧版安装文件。将发布包中的 `research-planner/` 内的 `main.js`、`manifest.json`、`styles.css` 放入测试 Vault 的 `.obsidian/plugins/research-planner/`，替换同名插件文件；保留自己的 `data.json`。
2. 在 Obsidian 社区插件设置中启用或重载 Research Planner。要求 Obsidian 1.13.0 或以上。
3. 在内置 **Daily Notes（日记）** 设置日记目录、日期格式和模板。推荐新 Vault 配置是 `10 Daily`、`YYYY/MM/YYYY-MM-DD`、`99 System/Templates/Daily`。模板中应包含 `## Tasks`。
4. 在插件设置中填写 API 基础地址、模型 ID，并通过 SecretStorage 配置本机密钥。API 基础地址不含 `/chat/completions`。可以先“测试连接”，此操作只发送合成数据。
5. 每台设备分别开启“允许本设备写入”。若存在 `99 System/Automation/Research Workflow Config.md`，其中顶部 YAML 的 `planner.enabled` 也须为 `true`。插件不自动更改该开关。修改该配置后，旧草稿须点击“重新读取并复盘”重新生成；“更新草稿”只迭代旧快照。配置变化导致的拒绝发生在任何笔记写入之前。
6. 在独立测试 Vault 确认流程后再安装到正式 Vault。Windows 和 Ubuntu 使用同一份插件文件；正式 Vault 未被开发测试修改。

0.3 系列首次确认时，将跨日清单升级为 version 2，并在其中维护日记任务的身份与处理记录。0.3.1 增加父级信息，0.3.2 增加已清空清单的边界记录；读取兼容旧数据。其他设备需同步升级至 0.3.2，旧版不能读取新增字段。保留升级前的跨日文件及笔记备份；本机最近一次撤销可以恢复该次写入的原文和状态。

旧版 API 设置可以沿用，但 v0.2 的设备写入开关默认重新关闭。旧版 `50 Planning/Research Planner Tasks/` 与 Reviews 文件保留，不自动迁移、不自动读取。将仍需继续的旧任务手动放入今天的 `## Tasks`，不要同时把同一任务再加入跨日清单。

## 日常使用

0.3.5 将日期、指代和任务拆分交给模型理解，代码只校验结构一致性及 Vault 写入边界，不再通过日期正则覆盖计划。原有“无日期尽快做、不按负荷延期、不编造时段”的偏好保留；模型理解仍需核对预览。

可以点击“只解释，不改计划”询问原因或讨论选项；点击“发送 / 调整计划”落实修改。模型支持只提交变化条目，其余草稿保持，程序合并后再次完整校验。问题、回答和校验结果按顺序显示并进入下一轮上下文。旧日记原文作为补充上下文提供，规划范围仍限任务清单及明确用户意见。

同日重启会恢复已保存且未接受的讨论，但必须重新读取日记后生成草稿；“开始新对话”清空活动上下文，历史记录仍可查看。未接受的讨论不写入日记。

日期可以使用 `10-16`、`10/16`、`16号`、`16~18日`、`17和18号` 等自然写法，由模型结合原文日期和上下文理解，不局限于这些格式。多日活动或提醒可以拆分；真正有歧义时澄清。反馈不必重复完整任务标题。

“会话记录 / 复制”保存并显示每次请求、用户意见、原始回复、本地处理及错误。原提议、本地改写与错误也传给下一轮模型用于修正。记录在插件目录中跨重启保留，含私人任务，不含 API key；存储路径、清理和同步边界见 [安装与排错说明](docs/INSTALL.md#会话记录与升级排错034-起)。模型说明是校验前输出，最终日期以预览为准。

0.3.3 会显示实际处理总数（未完成任务 + 待检查完成记录 + 跨日任务）。新安装的输出预算为 16384 token，已有配置保持不变；截断时可点击“提高上限至 … 并重试”，最高 32768。该操作保存设置并发起一次新请求，不会自动循环或写笔记。服务端若报告用量，错误中会显示输出和推理 token 数；缺失的统计不作猜测。

生成失败后，上一次成功的预览保留为不可接受的旧稿；没有成功草稿时会显示原因和重试入口。完整新草稿生成后才恢复“接受并写入”。

白天直接写日记：

```markdown
## Tasks

- [x] 整理实验记录
- [ ] 分析实验数据
- [ ] 周五提交周报
```

先人工检查完成状态，删除不再需要的任务，再打开侧栏 **日记复盘**：

1. 选择 **安排哪一天：今天／明天**，保留 **接续旧日记 TODO → 最近一份 TODO（默认）**，然后点击 **开始复盘**。白天和晚上均可操作。
2. 检查来源日期、遗漏任务、今日说明、目标日程，以及跨日任务的去向。“安排今天”原位调整当日未完成任务并接入遗漏任务；“安排明天”合并新增任务并保留明日已有内容。
3. 如需调整，输入“组会改到 15 点，明天优先分析数据，不用排具体时间”，点击 **更新草稿**。可以多轮讨论。
4. 没有待确认问题或时间冲突后，点击 **接受并写入**。可展开查看全部拟写内容，包括旧日记的任务去向。尚未提交的输入也会阻止确认，避免误用旧草稿。

### 漏做一天或多天

先在最近那篇含 TODO 的日记里勾选已完成项、删除不需要的任务并追加新任务，再生成今天或明天的安排。默认优先使用今天的清单；今天没有清单时，向前查找最近 30 天，只接续最近一份。来源日记即使已经复盘确认过，也会重新读取当前内容。面板明确显示来源日期，不要求逐日补做总结，也不混入更早版本的清单。

没有明确另定日期的未完成任务安排到所选今天／明天。已到期或过期的跨日任务默认一起接续，不允许模型仅用 keep 让它们无限滞留；用户明确要求暂不安排的例外仍保留。截止期限为空并不表示任务不需要安排日期。

已勾选任务保持完成；最新清单全部完成，或已登记清单被清空时，不向更早的日记寻找替代任务。找不到清单会显示 30 天查找范围；更早的任务请整理到今天。没有读取过的空日记无法区分是空模板还是曾手动清空的清单，请核对面板来源日期。

旧的多日合并方式保留在 **任务来源 → 按日期范围合并（高级）** 中，此模式按上次确认后的日期／手动起始日读取，最多 30 天。仅在确实要汇总多份独立日记时使用。不会枚举整个 Vault，不读取项目主页或 Planning。缺失旧日记不创建。

当前输入上限为 150 项待处理任务、90,000 字符的日记及任务上下文；超过时要求缩小范围，不静默丢弃。

确认前所有变化都只是草稿；未来任务也尚未登记。未提交的输入保存在本机，关闭/重载后可以继续填写。生成草稿和已提交的讨论只在本次插件运行期间保留，重载后需重新复盘。请求中关闭面板时，迟到的回复会被忽略，不弹出面板、不写笔记。

只有 `## Tasks` 范围内的 Markdown `- [ ]`（含缩进和有序列表）作为未完成任务，`[x]`/`[X]` 视为原工作完成，但仍会检查其中明确写出的后续工作（包括紧随其后的缩进补充，不包括另一个子任务）。普通完成记录不会凭空生成后续任务，空白模板待办、代码块以及其他章节不作为新任务来源。章节名可在设置中修改。

## 已完成工作还有后续

可以保留这样的日记写法：

```markdown
## Tasks
- [x] 今天完成初步调试，后续10月9日继续验证稳定性
- [x] 完成初稿
  明天补充实验结果
```

复盘时会单独展示“从完成记录提取的后续工作”。后续任务仅包含剩余工作，原勾选与原文字保留。日期或具体动作不明确时先提问；一条记录包含需分别安排的多项后续时，先请你拆成独立待办或在面板明确补充，避免默默漏掉部分工作。面板可用自然语言纠正误识别，接受前不登记任何后续任务。

确认时，检查记录保存在跨日文件的数据区，完成项行尾不再添加 `rp-reviewed` 摘要。相同文字再次复盘时不重复提取，即使后续已经交给另一篇日记也不复活。修改完成项正文或紧随的缩进补充会重新检查；模型需结合已有待办、明日任务及跨日清单避免重复。撤销会连同处理记录一起还原。单独删除后续任务不意味着自动再次生成，可在面板显式重新安排。

所有完成项都已经勾选、但还没有检查记录时，也会调用模型进行检查。普通完成项会显示为“原条目保持完成，无新增后续”；记录只有在接受后才保存。

## 确认后写到哪里

| 内容 | 位置与行为 |
| --- | --- |
| 原任务的去向 | 今日日记及补读旧日记保留文字与“已转至 / 已登记跨日任务 / 已取消”；链接后没有任务 ID；完成项保留勾选 |
| 简短说明 | 当日日记新增或更新 `## 日程安排`（今天模式）或 `## 晚间复盘`（明天模式） |
| 目标任务 | 今天模式原位调整当日任务；明天模式保留明日已有任务并合并新增项；缺少目标日记时使用模板创建 |
| 未来任务及处理记录 | `99 System/Automation/Research Planner Future.md` 单一文件的数据区 |

跨日文件上方 YAML 属性为任务数据，下方是阅读视图；请通过面板的自然语言意见修改或取消。任务确认写入目标日记后就退出清单，由那篇日记的勾选、编辑和删除管理。到期但尚未交接的跨日任务仍会供下次决定。

“留在原日记”与“存入跨日清单”含义不同，预览中会明确区分。遗漏任务只在本次显示的补读范围内查找，不会无限回溯。

任务内部标识保存在跨日文件的 `diaries` 数据中，不再散落在日记。旧的 `rp` ID 与 `rp-reviewed` 摘要会在相关日记参与确认写入时迁移并清理；链接、勾选、无关正文、代码示例保留，不全库清理。复盘区域仍保留一对不含任务 ID 的边界注释，用于安全更新总结。

身份按日记路径和任务正文/缩进补充关联，移动行位置、勾选不改变未改文任务的身份；手工改写正文视为新内容，完成项后续会重新检查。同篇日记同一父级内完全相同的任务须补充文字区分；不同父级允许同名步骤。删除日记任务后，状态区不会把它恢复出来。状态区仅保留最近 30 天及明日的任务身份；这是补读范围内的处理记录，不是待办来源或永久备份。

## 模板、时间与平台

- 内置 Daily Notes 设置决定路径与模板。支持 `{{date}}`、`{{date:格式}}`、`{{title}}`，创建明日日记时按目标日期展开。模板有其他未识别变量或 Templater 脚本时停止，不假装执行成功。
- 无时间任务不强制估时或分配时间块。有明确时间可写成 `- [ ] 15:00 - 16:00 组会`；只知道开始时间则保留开始时间，不推测时长。
- 未来安排日期与截止日期分别处理，截止日可用 `📅 YYYY-MM-DD` 显示。支持相对日期理解，但请在预览中检查模型解析结果。
- 时间轴插件尚未确定，本版提供时间文本格式，未安装或联调某个时间轴插件。手机日历账户同步未实现。
- 明日日记已有任务保持原样。如果要调整它们，请先在日记手动修改，再点击“重新读取并复盘”；今天模式支持调整当日未完成任务。切换目标日期或补读范围后旧草稿失效，需重新生成。
- 默认时区 `Asia/Shanghai`。复盘跨越午夜后须重新读取，避免把昨天草稿写错日期。
- 可选晚间提醒只通知，不读取任务或调用模型；应用关闭时不执行，漏掉几天可以在下次手动生成时统一补读。提醒是本机设置，双设备可只开启一台。
- 插件无 Node/Electron 运行依赖，已开放移动端加载并提供窄屏布局；**开放加载不等于 Android 已实机验收**。Windows、Android 和真实 LiveSync 跨设备联调仍须单独验收。

## 写入保护与恢复

确认前检查今天、明天、全部补读日记（包括当时不存在的日期）、跨日清单和使用的模板/日记设置是否变化。任何冲突都会停止，要求重新读取。模型输出漏任务、重复 ID、未知 ID、未解决的问题和能识别的时间重叠也会阻止写入。

多文件操作先保存本机恢复记录，再依次写入。中途失败尝试恢复原内容；若检测到后续人工或同步修改，则保留恢复记录并拒绝覆盖。面板 **恢复 / 撤销** 可恢复最近一次操作。新建文件撤销后保留为空文件，不删除文件。

若出现“未完成写入”，先使用恢复入口。后续修改导致恢复被拒绝时，核对面板列出的文件，保留你的新编辑，再处理重复或部分交接；不要反复确认旧草稿。恢复记录只在本设备保存，不能替代独立备份。

LiveSync 可以同步普通 Markdown 日记和跨日清单，插件不控制同步服务。本机快照保护不能保证两台设备离线同时编辑时的分布式原子性；在一台确认后，应等另一台同步完成再继续操作。

## 开发与测试

本仓库根目录就是插件源码目录，不依赖仓库外的 dev.cmd 或便携 Node 路径。使用 Node.js 22 和锁定依赖：

```sh
npm ci
npm test
npm run build
```

构建包含 TypeScript 检查，输出 main.js；运行时还需 manifest.json 和 styles.css。打包方式见 [安装指南](docs/INSTALL.md)。

可选的 npm run test:live 从运行时环境读取 API_BASE_URL、API_KEY、MODEL_NAME，仅发送合成任务并使用额度，不是安装必需步骤。不得把真实 key 写进可提交文件或命令参数。GUI 脚本 npm run test:obsidian 创建独立合成 Vault，需通过 OBSIDIAN_EXECUTABLE 指定可执行程序；Linux 还可设置 RWA_TEST_DISPLAY、RWA_TEST_LIBS。Windows GUI 脚本尚未实机验收，不能把单元测试当成 GUI 验收。

当前验证与限制见 [测试记录](docs/VALIDATION.md)。0.1 核心模块保留为历史回归，新界面使用 src/daily.ts，不运行旧版项目/Planning 搜集逻辑。测试范围限定到 tests，不执行 .test-runtime 中的备份。
